## 二、这一轮新出现的问题

### 新问题 1：第 2 屏屏幕文字行 27 `PS&gt; python -m verisolv  --demo`
`PS&gt;` 是 HTML 转义残留（`>` 被写成 `&gt;`）。这在视频里如果原样显示，评委会看到 `PS&gt;` 而不是 `PS>`。这是 build_video.py 导出 bug，必须修。

**改法**：把 `PS&gt;` 改成 `PS>`。第 4 屏行 55 同样的问题。

### 新问题 2：第 2 屏屏幕文字只有 5 行，信息量太少
上一轮第 2 屏有 `converged: False`、`failure: max_iterations`、`increments accepted: 3` 等关键输出，这一轮砍到只剩：
```
converged          : False
failure            : max_iterations
load reached       : 6,000.0 N of 20,000 N requested
程序加到 6,000 N 就停住了，目标是 20,000 N
```
**`failure: max_iterations` 这行评委看不懂**——"max_iterations"是什么？为什么超了 max_iterations 就失败？屏幕没解释，旁白也没解释（旁白只说"程序只加到六千牛就停住了，因为再往下算，方程没有解"）。评委会看到 `failure: max_iterations` 然后不知道这跟"方程没有解"有什么关系。

**改法**：要么删掉 `failure: max_iterations` 这行（信息冗余，旁白已经解释了），要么在屏幕上加小字注释"max_iterations：迭代次数上限"。

### 新问题 3：第 4 屏屏幕文字行 57 `[ACCEPTED] displacement_control   converged=True  verdict=verified`
`[ACCEPTED]` 是程序内部状态标签，评委不需要看到。`displacement_control` 是下划线连接的英文，第 6 屏已经改成了中文"修复失败 · 检查模型 · 跑测试案例"，但第 4 屏这里还是裸英文。

**改法**：把 `[ACCEPTED] displacement_control   converged=True  verdict=verified` 改成中文：`位移控制    收敛=成功    验证=通过`。或者删掉这行，只保留 `solved: True` 和 `verification: verified`。

### 新问题 4：第 4 屏旁白行 65 "约七千九百五十八牛"
"约"字太模糊。屏幕写 7,957.6 N，旁白说"约七千九百五十八牛"——"约"暗示不精确，但 7,957.6 是精确值。而且 7,957.6 ≠ 7,958（四舍五入是 7,958，不是 7,958）。"七千九百五十八"是 7,958，但屏幕写 7,957.6。

**改法**：旁白改成"极限载荷为 7,957.6 牛"（跟屏幕精确对齐），或者屏幕改成 `7,958 N`（四舍五入），旁白"约七千九百五十八牛"。

### 新问题 5：第 7 屏屏幕文字行 117 "用于估算位移的检查公式偏小 890 倍，从未真正生效"
"偏小 890 倍"语病——上一轮我指出的"偏小"是形容词、不能接"890 倍"，这一轮没改。

**改法**：改成"位移估算公式偏差达 890 倍，该检查从未生效"。

### 新问题 6：第 7 屏屏幕文字行 114 "检出一步位移跳变为前一步的 156.2 倍"
"一步位移跳变"——"跳变"是物理术语，但这里说的是"位移突变"，不是"跳变"（跳变一般指物理量的不连续突变，这里其实是"这一步的位移量是前一步的 156.2 倍"，不是"跳变"）。

**改法**：改成"检出某步位移为前一步的 156.2 倍"。

### 新问题 7：第 8 屏屏幕文字行 131 "离散误差的评估方法已实现，但它判定我们的数据不满足使用条件"
"它判定"——"它"指代不明。是"离散误差的评估方法"判定？还是"程序"判定？上一版写的是"它判定我们的数据不满足使用条件"，主语模糊。

**改法**：改成"离散误差评估方法已实现，但该数据不满足其收敛条件，故未给出误差范围"。
