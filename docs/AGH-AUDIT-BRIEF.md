# AGH 智能体审计任务书（对抗性证伪）

> **读者：Agnes Harness 智能体。**
>
> 这不是一份"请审查一下"的任务。**"请审查"会得到客套话。**
> 这是一份**证伪任务**：下面每一条都是项目对外宣称的结论，**你的任务是把它推翻**。
>
> 找到反例就是成功。找不到反例，你要说清楚**你试过哪些方法、为什么没找到**——
> "我看了，没问题"不算结论。

**背景**：项目已完成三轮修复，代码已封版。队长现在要提交参赛材料，
**他需要知道哪些结论经得起攻击、哪些经不起**。经不起的现在改还来得及，
提交之后被评委发现就晚了。

---

## 0. 铁律（比上一轮更严）

1. **不许修改任何文件。** 这一轮你**只读、只跑、只报告**。一个字节都不许写。
   （可以在 `docs/` 下**新建**一份 `audit-report.md`，这是唯一的写操作。）
2. **不许编造。** 说某个数字错了，就贴出你算出来的数和它的来源。
3. **不许客气。** 不要写"总体质量较高，建议……"。**只写你找到的问题。**
4. **找不到问题也要报告方法。** "我尝试用 X、Y、Z 三种方式攻击这条结论，都没成功，
   因为……"——这才是有价值的结论。
5. **区分"错误"与"表述不清"。** 两者都要报，但要标清楚是哪种。

## 1. 八条待证伪的结论

对每一条，**尝试用一切手段推翻它**，然后如实报告结果。

### C1：求解器算得对

> 项目声称：非线性有限元的闭式解一致性达 6.106e-16 / 4.579e-16 / 2.345e-16（相对误差）。

**怎么攻击：**
- 闭式解函数在**两个地方**有实现：`tools/check_physics.py:30` 和 `verisolv/cases.py:556`。
  **先确认这两份是不是同一个公式**（逐行读，不要只比较输出——如果两份是同一个错误公式，输出当然一致）。
- 这个闭式解**推导本身**对不对？它是浅拱两杆桁架的解析解。
  去核对它的**推导前提**是否与 `fem.py` 的有限元假设一致（Green-Lagrange 应变、PK2 应力）。
- 换一个**完全不同的载荷路径**再比一次（不要只用位移控制的那三个挠度）。
- 试试**超出闭式解适用域**的挠度（比如 v > rise），看两边还一致吗？如果不一致，是谁错了？

### C2：跨库交叉验证独立

> 项目声称：与独立库 PyNiteFEA 交叉验证达 6.8e-8。

**怎么攻击：**
- 这个 6.8e-8 是**什么物理量**的误差？载荷？位移？应力？**相对还是绝对？**
  如果文档没说清，这本身就是问题。
- 交叉验证的**对照条件**是否等价？PyNite 是线性梁/桁架程序，
  而本项目是**几何非线性**。如果对照的是小变形工况，那**它们本来就该一致**，
  这条验证的信息量有多大？
- 去看 `tools/cross_validate.py`：它比的是**哪个量**？有没有"调参调到一致"的嫌疑
  （比如那个 `TINY_I` 惯性矩——查查它是干嘛的，为什么需要它）。

### C3：四道验证闸门的独立性与有效性

> 项目声称：四道闸门中两项不独立（复用 same assemble），真正独立的对照是解析解与独立库。

**怎么攻击：**
- **构造一个反例**：有没有一种错误，**四道闸门全过、但答案是错的**？
  盲测里的 B01（载荷反向）是一个。**还有别的吗？** 试着找出第二个、第三个。
- `jump_factor = 20.0` 这个阈值是**硬编码**的。**它是怎么来的？** 去代码里找依据。
  如果找不到依据，就实测：构造一批正常收敛的路径，看增量的最大/中位比分布；
  再构造已知的跳分支路径，看分布。**20.0 落在哪？** 太松会漏判，太紧会误判。
- `step_refinement` 的容差是多少？和残差收敛容差（1e-6）比，**量级是否合理**？
  一个比收敛容差还紧的细化判据，是不是在测噪声？

### C4：案例库 20 例全过

> 项目声称：可检测错误 9/9 抓中、阳性对照 9/9 干净、修复行为 20/20、漏抓 0。

**怎么攻击：**
- 这 20 个案例**都是出题人自己设计的**。去 `verisolv/cases.py` 逐个读案例定义，
  找出**任何一个设计得不公平、或者期望值可疑**的案例。
- 特别看 `E01_boundary_load_exactly_at_limit`：它的 `expected` 列了**三个**可能结果
  （`LIMIT_POINT, CONVERGED_UNVERIFIED, CONVERGED_VERIFIED`）。
  **一个接受三种结果的测试，还能算测试吗？**
- 看 `expected` 列表普遍有多宽。**期望值越宽，测试越弱。** 统计一下平均宽度。
- `repair_should_help` 这个标签是出题人打的。有没有哪些案例，
  **出题人把标签打成了"符合实际结果"而不是"符合应该"**？

### C5：优化结果可信

> 项目声称：209.26 kg → 128.72 kg，减重 38.5%，292 次评估，verdict=verified。

**怎么攻击：**
- **`verified` 只证明这一个解是可信的，不证明它是最优的。** 文档里有没有
  **把"验证通过"说成"最优"**？去 README、verification.md 逐句找。
- README 里的 38.5% 有没有和 `runs/` 里的实际数据对得上？**重跑一遍比对。**
- 那个"独立复核 PASS"是怎么做的？是独立实现，还是又调了一遍同一个 `evaluate()`？

### C6：两个极限载荷数字

> 项目里同时流通 **7963.16 N** 和 **7957.7 N**。

**怎么攻击：**
- 找出这两个数**各自的确切来源**（哪条命令、哪次运行、哪个文件）。
- 差 5.5 N（0.07%）的解释是"采样步长/末增量"。**这个解释经得起检验吗？**
  改步长重跑，看 7957.7 会不会变；如果会变，说明它是**离散采样最大值**，
  那么**7963.16 是怎么得到"精确"值的**？两者的关系是什么？
- **结论：提交材料里到底该写哪个数？** 给出明确建议和理由。

### C7：AGH 执行记录满足"可供人工核查"

> 赛事要求：上传**可供人工核查**的 AGH 执行记录。

**怎么攻击：**
- 读 `docs/agh-execution-record.md`，**假装你是一个不懂技术的评委**。
  你看完能判断"AI 到底干了什么核心工作"吗？哪里看不懂？哪里信息不足？
- 记录里的**工具调用链**是完整的吗？有没有只写结论不写过程的段落？
- `docs/agh-role.md` 里的"使用环节"描述，**和实际发生的事对得上吗**？
  有没有夸大？（比如声称 AI 做了实际由人做的判断）

### C8：可复现性

> 项目声称：`docs/reproduce.md` 写清了怎么从零跑起来。

**怎么攻击：**
- **逐字照做**，但**每一步都检查它是否真的说清了**：Python 版本？依赖包和版本？
  路径假设？环境变量？
- **模拟全新环境**：如果一个人把项目拷到 `D:\test\project\`，
  `reproduce.md` 里的命令还能跑吗？**去里面找硬编码的本机路径。**
- `runs/` 和 `figures/` 里的产物是**当时生成的**还是**重新生成的**？
  如果别人重跑，数字会不会变？**reproduce.md 有没有说清"哪些数字必须一致、哪些允许有小差异"？**

## 2. 还要做的三项横向检查

### 2.1 文档之间有没有自相矛盾

**12 份文档**，由不同轮次写成。逐份读，**列出所有互相矛盾的陈述**。

方法建议：先抽出一批"事实性断言"（数字、因果、能力声明），再逐份对照。
不要只做关键词搜索——**矛盾常常是措辞不同而不是数字不同**。

### 2.2 有没有"说过头"的地方

全项目搜一遍这些词：
```
证明 / 保证 / 完全 / 全部 / 独立 / 精确 / 最优 / 无误 / 确保
```
**每一处都问：这个强度站得住吗？** 特别是"独立"和"证明"。

项目立身之本是诚实，**一处说过头就毁掉全部可信度**。

### 2.3 有没有未披露的局限

去读代码，找出**项目文档里从未提到、但确实存在的局限**。例如：
- 单元类型只有 2 节点桁架杆（不能受弯、不能受剪）
- 只支持一个载荷工况
- 只有平面问题
- 屈曲只考虑欧拉/约翰逊，没有局部屈曲、没有整体-局部相关
- 材料只有线弹性
- ...

**每找出一个，就检查：文档里说了吗？** 没说就是**未披露的局限**，必须补。

## 4. 分级标准（用这个，不要自己发明）

- **阻断**：结论是错的，或者提交材料里有事实错误 → **必须改，否则影响参赛**
- **重要**：结论对但表述会误导，或存在未披露的局限 → **强烈建议改**
- **次要**：措辞、格式、可读性 → **有时间就改**
