## 二、时间轴

### 0:00 – 0:18 ｜【任务输入】

**画面**：窗口①。**敲完整条命令再回车**（让观众看清输入）：

```powershell
& $PY tools\demo_closed_loop.py
```

**屏幕字幕**：

```
任务：求这个浅拱的极限载荷
参考载荷 20,000 N
```

**【旁白】**

> 我们让它做一件事：求这个浅拱能承受的最大载荷。
> 参考载荷两万牛。它要告诉我们，这个结构在哪个载荷上失去稳定。

---

### 0:18 – 0:50 ｜【异常处理】

**画面**：窗口① 输出停在第 1 段（**实跑输出，已核对**）：

```
STEP 1  first attempt: load control, no adaptivity
converged          : False
failure            : max_iterations
load reached       : 6,000.0 N of 20,000 N requested
```

**切到窗口②**（`equilibrium_path.png`），停 8 秒。

**屏幕字幕**（红色）：

```
载荷控制失败
只加到 6,000 N of 20,000 N

图上有一条跳变：
最大增量 = 中位增量的 1058.6 倍
分支跳变 = 0.178 m
```

**【旁白】**

> 第一次尝试失败了。它只加到六千牛，迭代就停住。
> 这里的诱惑是调小步长，让它继续算，然后报一个数字出来。
> 但问题不在步长。看这条曲线——在极限点附近，迭代跳到了一条完全不同的平衡路径上。
> 那条跳变是零点一七八米，相当于中位增量的一千零五十八倍。
> 这不是数值噪声，这是跳轨了。

---

### 0:50 – 1:25 ｜【执行过程 + 反馈调整】

**画面**：切回窗口①，**继续往下滚**同一份输出（**实跑输出**）：

```
STEP 2  the solver's own claim is not evidence
The run did not converge, so there is no state to verify.

STEP 3-5  diagnose, repair, re-verify
diagnosis          : limit_point
attempts:
  [ACCEPTED] displacement_control   converged=True  verdict=verified

solved             : True
verification       : verified
```

**屏幕字幕**：

```
诊断：limit_point
反馈调整：载荷控制 → 位移控制
重算：穿过极限点 → verified
```

**【旁白】**

> 第二步是关键：求解器自己的说法不算证据。它没收敛，所以没有状态可以验证。
> 然后它自己诊断：这是极限点——平衡路径走到了极大值，切线刚度奇异，任何载荷增量都无法前进。
> 于是它做了一个决定：切换到位移控制。因为这是唯一能越过极限点的方法，载荷控制永远过不去。
> 重算之后，它穿过了极限点，而且结果通过了验证。

---

### 1:25 – 2:05 ｜【外部能力调用】

**画面**：切到窗口⑤（**AGH 网页的 Trace**），停 6 秒——**要让评委看到工具调用链**。

**切到窗口④**（`blind-diagnosis.md` 的 F6 节）。

**屏幕字幕**：

```
Agnes Harness · agnes-3.0-flash
调用 6 个工具：verisolv_models / solve / verify / repair / checkmodel / cases

盲测：8 个案例库里没有的新故障
它发现一个检查偏小 890 倍、从未生效
它拒绝迁就出题人的标准答案
```

**【旁白】**

> 比赛要求智能体参与核心任务，不是当个聊天框。
> 通过 Agnes Harness，模型调用六个工具来驱动求解、验证、诊断和修复。
> 我们给它八个案例库里没有的新故障类型，让它自己判断系统该不该抓到。
> 它发现了一个我们没发现的 bug：一个检查用来估计位移的公式偏小了八百九十倍，
> 所以那个检查从来没有生效过。
> 更重要的是，出题人的预期答案和实测不符，它没有改答案去迁就，而是写下"不一致"。
> 一个会说"我不知道"的系统，比一个什么都能答的系统有用。

### 2:05 – 2:40 ｜【结果验证】

**画面**：切回窗口①，执行：

```powershell
& $PY -m verisolv checkmodel --model von_mises_truss
```

然后**切到窗口③**（`catch_matrix.png`）。

**屏幕字幕**：

```
四道闸门   残差 · 全局平衡 · 路径连续性 · 步长细化
外部对照   闭式解 6e-16 · 独立库 6.8e-8

20 个标注案例：可检测 9/9 抓中 · 阳性对照 9/9 无误报
原理上检测不到 2 条 —— 如实列出
```

**切回窗口①** 执行：

```powershell
& $PY -m verisolv cases --strict
```

输出：`{"strict": "passed"}`

**【旁白】**

> 它给出的极限载荷是七千九百五十七点六牛。闭式解是七千九百六十三点二牛。
> 四道验证闸门——残差、全局平衡、路径连续性、步长细化——全部通过，
> 而且和教科书闭式解对到机器精度。
> 支撑这一切的是二十个标注案例，根因都是构造时已知的。
> 九个可检测错误全部抓中，九个阳性对照一个都没误报。
> 另外两条抓不到的错误，它自己在图上标成了"原理上检测不到"。

```
一个会自己复核自己的结构仿真智能体
```

**【旁白】**

> 最后说我们没有什么。

> 载荷方向、单位、截面积量级这三类错误，我们的检查器抓不到。
> 这个项目不保证给你答案。它保证告诉你，这个答案能不能信。
