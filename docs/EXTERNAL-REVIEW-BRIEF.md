## 1. 项目是什么

**名称**：verisolv —— 一个会自己复核自己的非线性结构仿真智能体

**一句话**：非线性有限元求解器有一种**沉默的失败**——迭代收敛了，但收敛到了**另一个平衡分支**上，
求解器报告"成功"，工程师拿到一个漂亮数字，**而这个数字是错的**。
本项目把"怀疑"变成**可执行的、可证伪的检查**。

**技术内核**：
- 总拉格朗日平面桁架有限元（2 节点杆单元）
- Green-Lagrange 应变 / 第二类 Piola-Kirchhoff 应力 / 一致切线刚度
- Newton-Raphson，**载荷控制 + 位移控制双模式**
- 自适应步长、线搜索

**在求解器之上**：
- **四道验证闸门**：残差重建 / 全局力-矩平衡 / 路径连续性 / 步长细化复算
- **模型检查器**（不跑分析）：自由度计数、零载荷奇异值（机构检测）、杆件合法性、
  材料量级合理性、支反力可行性、尺度一致性
- **会升级策略的修复链**：诊断 6 类故障 → 换控制变量 / 细化步长 / 线搜索 / 稳健组合 →
  **每次尝试后重新诊断**（这是闭环，不是固定列表）
- **20 个标注案例库**，根因按构造已知
- **GCI（网格收敛指数）闸门**：载荷步细化的理查森外推 + 观测收敛阶 + 渐近区判定
- **MMS（制造解法）**尝试

**外部对照**：
- 闭式解对照（教科书解析解，相对误差 6.1e-16，**机器精度**）
- 独立库交叉验证（PyNiteFEA，6.8e-8）

**接口**：命令行 + 一个 AGH（Agnes Harness）插件（6 个工具），可脱离 AGH 独立运行。

## 3. 项目宣称的结论清单（**待你证伪**）

### C1 求解器算得对

> 闭式解一致性 **6.106e-16 / 4.579e-16 / 2.345e-16**（三条案例的相对误差）。

**怎么攻击**：
- 闭式解函数在**两个文件**里有实现（`tools/check_physics.py` 与 `verisolv/cases.py`）。
  逐行读，**确认是不是同一个公式**——如果两份都是错的，输出一致毫无意义。
- 这个闭式解的**推导前提**是否与有限元假设一致（Green-Lagrange / PK2）？
- 换**不同的载荷路径**、**不同的面积参数**再比一次。
- **超出小变形适用域**再比一次，看两边是否仍一致。

### C2 跨库验证独立

> 与独立库 PyNiteFEA 交叉验证 **6.8e-8**。

**怎么攻击**：
- 这个数是**什么物理量**的误差？载荷？位移？应力？相对还是绝对？
- `tools/cross_validate.py` 里有个参数 `TINY_I`，注释说是"把框架单元模拟成两力杆"。
  **查它是不是在"调参调到一致"。**
- PyNite 是**线性**程序，本项目是**几何非线性**。如果对照的是小变形工况，
  **两边本来就该一致**——那这条验证的信息量有多大？

### C3 四道验证闸门有效

> 四道闸门中两项不独立（复用同一 `assemble()`），真正独立的外部对照是解析解与独立库。

**怎么攻击**：
- **构造第二个、第三个"四道全过但答案是错的"反例**（已知第一个：载荷方向反向）。
- `jump_factor = 20.0` 是**硬编码的阈值**。**它有什么依据？** 项目自己承认"没有推导依据"。
  实测：正常路径最大/中位增量比 ≈ 1，已知跳分支 ≈ 1059。**20.0 合理吗？**
- `step_refinement` 的容差与残差收敛容差（1e-6）**量级是否匹配**？

### C4 案例库 20 例

> 可检测错误 **9/9** 抓中、阳性对照 **9/9** 干净、修复行为 **20/20** 正确、漏抓 **0**。

**怎么攻击**：

- **特别看 `E01_boundary_load_exactly_at_limit`：它的期望值列表列了三种可能结果**
