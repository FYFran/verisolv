## 1. 缺陷 ①：`check_scale_consistency` 实际上是失效的（**最重要**）

### 1.1 事实（队长已独立复现）

`verisolv/verisolv/checkmodel.py` 里的 `check_scale_consistency` 用这个式子估计位移：

```python
stiffness_scale = sum(bar.modulus * bar.area / bar.length(...) for bar in model.bars)
estimated = max_load / stiffness_scale
```

**这个 `stiffness_scale` 不是结构刚度，是所有杆件轴向刚度之和。**

对参考悬臂（`verisolv/cases.py` 的 `_cantilever`，17 根杆）：
- 该和 = **5.004e9 N/m**
- 而载荷实际感受到的尖端刚度 = **5.63e6 N/m**
- **差 890 倍**

### 1.2 后果（实测，载荷逐级放大）

```
载荷        估计位移      实际位移      估计/实际    检查结果
-50,000     9.99e-06 m   8.88e-03 m   0.0011      PASSED
-500,000    9.99e-05 m   8.82e-02 m   0.0011      PASSED
-5,000,000  9.99e-04 m   8.17e-01 m   0.0012      PASSED
-50,000,000 9.99e-03 m   4.17e+00 m   0.0024      PASSED   ← 1.41 m 跨度的结构位移 4.17 m
```

**结论：这个检查对"载荷型过载"从来没有生效过。** 它只在**刚度本身出错**时触发
（你的 F7 案例 E=1e3，刚度之和崩塌，才触发）。

### 1.3 队长已经量过的候选修法（**用数据选，不要凭感觉**）

```
            估计/实际（1.0 为完美）
载荷        现状      对角估计    线性解
nominal     0.0011    0.0268     1.001
x10         0.0011    0.0270     1.007
x100        0.0012    0.0291     1.087
x1000       0.0024    0.0572     2.132
```

- **对角估计**（`u_i ≈ F_i / K_ii`，不用解方程）：仍然差 37 倍，**救不了**
- **线性解**（`K_ff u = f` 解一次）：线性区**精确**（1.001），大变形时高估 2 倍
  —— **高估是警告该有的方向**，所以可用

### 1.4 约束（**必须遵守**）

1. **不能调用非线性求解器。** `check_model` 的价值在于"不跑分析"——
   它可以在分析已经失败之后被咨询，而且它的判断不继承求解器的假设。
   用 `np.linalg.solve` 解**一次线性方程**是可以的：线性系统不需要 Newton 迭代、
   不需要载荷步进、不需要路径跟踪，**不继承任何非线性机制**。
   它共用 `assemble()`，而 `check_rigid_body_modes` 早就这么做了。
2. **奇异矩阵不能崩。** 机构（F4 那种）会让 `K_ff` 奇异，`np.linalg.solve` 会抛
   `LinAlgError`。必须捕获并**如实说明"无法估计"**，不能返回一个假的数。
   **但也不要因此判 FAIL** —— 那是 `check_rigid_body_modes` 的职责，重复判会双重计数。
3. **保持 `Finding` 的数据结构不变**（`check` / `passed` / `severity` / `detail` / `evidence`）。
   下游（插件、案例库、CLI）都读这些字段。
4. **把这段历史写进函数的 docstring。** 这个检查曾经是死的、被盲测发现——
   这是项目的诚实性要求，不许省略。

### 1.5 修完必须证明

1. **x1000 载荷下 `check_scale_consistency` 必须 FAILED**（现在错误地 PASSED）
2. **标称载荷下必须仍然 PASSED**（不能变成误报机器）
3. **F4 那种机构模型下不能抛异常**（`check_model` 应正常返回 `ill_posed`）
4. 记录修复前后的对比数据

### 1.6 阈值

现在是 `estimated > 0.1 * span` 判 FAILED。**你可以调整，但必须说明理由，
并给出调整后在各载荷级别下的触发情况。** 不要把阈值调到"什么都能过"或"什么都报警"。

## 2. 缺陷 ②：`cases --strict` 抛 KeyError

### 事实（已复现）

```powershell

```

```
{"ok": false, "error": "'accuracy'"}

```

### 原因

```python

    return EXIT_OK if data["summary"]["accuracy"] == 1.0 else EXIT_UNTRUSTWORTHY
```

`controls_false_alarm` 等），**用一个 `accuracy` 数字概括正是这个项目反对的做法**。

### 你要做的

**先去 `verisolv/cases.py` 的 `summarise()` 里核对现在到底有哪些键**，然后决定
`--strict` 应该检查什么。

**队长的建议方向**（你可以提出更好的）：`--strict` 应该在**可检测错误全部抓中、
阳性对照无误报、修复行为全部正确**时退出 0。也就是检查
`missed == []` 且 `controls_false_alarm == []` 且 `repair_mismatch == []`。

**不要**为了省事重新加一个 `accuracy` 键——那会退回被废弃的口径。
