## 1.4 问题来源

```
非线性有限元求解器存在一种"沉默的失败"：迭代收敛了，但收敛到了另一条平衡分支上。

此时求解器报告成功，工程师拿到一个数值上完全自洽、残差与平衡检验全部通过的结果，
而这个结果对应的是错误的问题。传统做法完全依赖工程师的领域经验去怀疑它——
没有可执行的判据，也没有可复现的流程。

这一失败模式在几何非线性问题（极限点、跳跃失稳、后屈曲）中尤其常见：
载荷控制无法越过平衡路径的极大值，迭代要么发散，要么跳到远端分支后"成功"收敛。

问题来源：结构仿真结果的可信度缺乏可执行、可复现、可审计的判据。
```

## 1.5 项目目标

```
把"怀疑"变成可执行的检查。具体目标：

1. 实现一个几何非线性桁架求解器（总拉格朗日格式），并能在载荷控制失效时自动切换
   到位移控制，从而越过极限点、给出极限载荷。
2. 在求解器之上建立一层可证伪的验证体系：对每个结果给出"可信 / 存疑 / 拒绝"的判定，
   并说明判定的依据。
3. 让系统能区分三类失败：数值失败（可修）、模型失败（须改模型）、以及"数值自洽但
   答错了问题"（原理上不可由数值检查发现）。
4. 用标注案例库量化系统的能力边界，并如实公开它抓不到的类别。
```

## 1.6 核心方法

```
【求解内核】
总拉格朗日平面桁架有限元：Green-Lagrange 应变、第二类 Piola-Kirchhoff 应力、
一致切线刚度；Newton-Raphson 迭代，载荷控制与位移控制双模式，自适应步长与线搜索。

【四道验证闸门】
  1. 残差重建      —— 把报告的解代回平衡方程，独立重建残差
  2. 全局平衡      —— 力与力矩平衡（力矩取变形后坐标）
  3. 路径连续性    —— 最大增量 / 中位增量比值，检测静默跳分支
  4. 步长细化复算  —— 加密步长重算，比较位移与载荷因子

【模型检查器】（不运行分析，因而不继承求解器的任何假设）
  自由度计数、零载荷奇异值（机构检测）、杆件合法性、材料量级合理性、
  支反力可行性、尺度一致性。

【会升级策略的修复链】
  诊断六类故障（极限点 / 分支跳变 / 发散 / 切线奇异 / 增量耗尽 / 刚体机构），
  按类升级策略（切换控制变量 / 细化步长 / 线搜索 / 稳健组合），
  **每次尝试后重新诊断**——这是闭环，不是固定的策略列表。

【外部对照】
  闭式解对照（教科书解析解，相对误差 6.106e-16，机器精度）
  独立库交叉验证（PyNiteFEA 3.2.0）

【标注案例库】
  20 个案例，根因按构造已知，覆盖正常 7 / 边界 4 / 失败 9 三类。
```

## 1.7 Agnes Harness 执行流程

```
1. 通过 agnes-plugin 把项目的六个能力注册为 AGH 可调用工具：
   verisolv_models / verisolv_solve / verisolv_verify /
   verisolv_repair / verisolv_checkmodel / verisolv_cases

2. 在 AGH 会话中，由 agnes-3.0-flash 承担以下职责：
   - 根据用户意图选择工具与参数（任务规划）
   - 调用工具并读取返回（能力调用）
   - 在结果之上做判断：这是数值失败还是模型失败？该不该抓到？为什么？
   - 在证据不足时拒绝给出结论，并如实标注缺口（反馈处理）

3. 全过程由 AGH 记录：每次 tool/call 与 tool/result 均带时间戳、哈希链与
   平台层合规信号（verifier/signal，tier-0），可导出为供人工核查的执行记录。

4. 已完成的 AGH 作业（均留有原始记录）：
   - 盲测诊断：对 8 个案例库之外的新故障类型，独立判断系统该不该抓到
   - 三个缺陷的修复与回归验证
   - 一次对抗性审计（该审计推翻了项目自身的两条结论）
   - 一次文档更正复核

【关键说明】AGH 的 verifier/signal 是平台层对工具调用的合规检查，
与本项目的四道数值验证闸门处于不同层面，两者不构成"五道独立闸门"。
```

## 1.9 使用环节

```
agnes-3.0-flash 在本项目中用于以下四个环节：

1. 故障诊断判断（核心）
   在盲测中，对 8 个案例库之外的新故障类型，判断"系统该不该抓到它"，
   并说明理由。这是确定性代码做不到的判断——代码只会输出 ok / ill_posed /
   mechanism，说不出"这是一类需要用新检查覆盖的错误"。

2. 缺陷修复
   根据盲测发现的缺陷，修改验证层代码，并重新验证回归基线。

3. 对抗性审计
   对项目自身的结论发起证伪攻击，找出并公开了包括"验证层公式错误"在内的多个缺陷。

4. 文档与证据整理
   整理测试样例（三类）、AGH 角色说明、可复现说明与执行记录。

【不使用的环节】求解器的数值计算、验证闸门的判定逻辑、案例库的期望值——
全部由确定性 Python 代码完成，模型不参与。
```

## 1.10 调用方式

```
通过 Agnes Harness（AGH）的插件机制调用：

- 插件：@hackathon/verisolv-agnes-plugin@0.1.0（Apache-2.0）
- 机制：插件以 ctx.extension() 取得扩展上下文，用 agnes.registerTool() 注册六个工具；
  每个工具的 execute() 以子进程方式调用本地 Python 命令行
  （python -m verisolv <子命令>），解析其 JSON 输出后返回给模型。
- 插件是薄适配层：全部业务逻辑在 Python 包内，插件不承载任何算法。
- 项目根与解释器由环境变量 VERISOLV_ROOT / VERISOLV_PYTHON 指定。

【可脱离 AGH 独立运行】核心包只依赖 numpy，命令行可直接执行：
  python -m verisolv {models|solve|verify|repair|checkmodel|cases}
```

## 1.11 验证方法

```
【内部自洽检查】四道闸门 —— 残差、全局平衡、路径连续性、步长细化

【外部独立对照】
  - 闭式解对照：教科书浅拱两杆桁架解析解，相对误差 6.106e-16 / 4.579e-16 / 2.345e-16
  - 独立库对照：PyNiteFEA 3.2.0，5 N 小载荷下顶点挠度相对差 6.794e-8
    （注：该值对应小变形线性极限；设计载荷 50 kN 处为 7.139e-4）

【标注案例库】
  20 个案例，根因按构造已知：可检测错误 9/9 抓中，阳性对照 9/9 无误报，
  修复行为 20/20 符合预期，漏抓 0。

【数值不确定度】
  已实现网格收敛指数（GCI，Roache 1994 / ASME V&V 20）闸门，用于评估载荷步细化的
  离散误差。在当前问题上，细化序列不在渐近区，闸门**正确判定为 reject**，
  因此本项目**不声称任何离散误差带**。

【外部对抗性验证】
  由独立评审者以证伪为目的发起攻击。评审推翻了项目关于验证层的两条结论并找出若干
  表述问题，项目已据此修复。评审同时确认求解器内核与优化结果无法被推翻。

【如实披露的边界】（详见 EVIDENCE.md）
  1. 四项闸门中 residual 与 global_equilibrium 复用同一个 assemble()，不算完全独立
  2. 载荷方向反向、单位量级写错、截面积量级写错三类错误原理上检测不到
  3. verify() 只验证数值自洽，不验证设计约束（约束由 optimize.evaluate() 检查）
  4. 优化为坐标模式搜索，不保证全局最优
  5. 仅支持 2D 桁架、线弹性、静力、单一载荷工况
```
