# 验证方法说明（四道闸门 + 模型检查器 + 修复链）

> 对应赛事"验证严谨性与异常处理"维度。所有数字逐字取自工具输出与 `runs/` 证据文件。

## 一、四道验证闸门（`verisolv/verisolv/verify.py`）

求解器返回 `converged=True` 是**声明**，不是证据。四道闸门各自重新推导求解器已声称的某件事，且用不同的信息：

| 闸门 | 证明什么 | 各自**不能**证明什么 |
|---|---|---|
| `residual` | 把报告的解代回平衡方程，独立重建残差（`rel = \|f_int − λf_ext\| / max(\|f_ext\|, 1N)`） | 只能证明"这个解满足这个方程组"，不能证明方程组是"你问的那个问题"；若单元公式本身错，残差也会算出"收敛" |
| `global_equilibrium` | 全局力 + 力矩平衡：内力逐节点自抵消 ⇒ 支反力 + 外载应为零系统；力矩取**变形后**坐标 | 同上，且若 `assemble()` 有系统性错误，力/矩两边同错，检查仍通过 |
| `path_continuity` | 平衡路径连续性：最大增量/中位增量比值，检测"静默跳分支"（分支跳变 0.178 m = 中位增量的 1058.6 倍） | 只能检测"路径是否连续"，对"连续但整体答错问题"（载荷反向、单位错误）无感 |
| `step_refinement` | 步长加密（×2）复算，解的位移/载荷因子相对差 1e-10 量级——不可复现的解不可信 | 复现的是**同一套代码**的解；若公式错，加密复算仍一致（差 0.0），不暴露公式错误 |

**判定逻辑**：critical 失败 → `rejected`；任一 major 失败 → `suspect`；全过 → `verified`。

## 二、为什么说"四项检查并非完全独立"

- `residual` 与 `global_equilibrium` **都调用同一个 `assemble()`**：`fem.py` 的单元内力/切线若有一处公式错，两项会**同时**通过。它们验证的是"自洽"，不是"正确"。
- 真正**独立**的外部对照只有两项：
  1. **解析解对照**（`cases.exact_apex_force`，无有限元的教科书闭式解）：R01/R02/R03 相对误差 **6.11e-16 / 4.58e-16 / 2.34e-16**（机器精度）。
  2. **独立库交叉验证**（PyNiteFEA 3.2.0，`runs/cross_validation.log`）：载荷梯梯上相对差
     （顶点挠度）：5 N → **6.794e-8**、50 N → 6.813e-8、500 N → 6.989e-8、5000 N → 8.814e-8、
     50000 N（设计载荷）→ **7.139e-4**。头条数字 6.8e-8 是**最小载荷 5 N（线性极限）**处的值；
     设计载荷处差 7.14e-4，比头条数字大 1 万倍。小载荷段是**平坦地板**（~7e-8，PyNite 侧
     框架单元模拟桁架的截断限制），并非"每降一个数量级差距同降一个数量级"——实测 5 N→5000 N
     始终在 ~7e-8 地板附近，到 50 kN 反而跳升 80 倍（非线性效应超出小变形对照的适用域）。
     完整梯梯见 `tools/cross_validate.py` 输出。
- 因此本项目的"verified"准确的定位是**自洽性检查 + 外部对照的组合**，而不是"四道相互独立的闸门"。这一点在评分里"验证严谨性"一项必须如实陈述，**不许美化**。

## 三、模型检查器（`checkmodel.py`，不跑分析）

四道闸门回答"这个答案和它来自的模型自洽吗"；模型检查器回答互补的"这个模型本身是否良定、是否可信"。用确定性检查（**不继承求解器的任何假设**）：

| 检查 | 类型 | 作用 |
|---|---|---|
| `degrees_of_freedom` | 确定性 | 约束数 vs 平面桁架 3 个刚体自由度 |
| `rigid_body_modes` | 确定性（零载荷 SVD） | 机构（刚体模态）判定 |
| `member_properties` | 确定性 | 长度/面积/模量/屈服应力正值 |
| `material_plausibility` | 启发式（量级带 1e6–1e12 Pa） | 材料常数量级写错（**这是四道数值闸门原理上盲的**） |
| `reaction_feasibility` | 确定性 | 每个净载荷分量是否有约束可平衡 |
| `scale_consistency` | 启发式 | 载荷-刚度-位移是否"同族" |

**诚实边界**（必须继承）：模型检查器抓不到的东西已如实记录——
- `material_plausibility` 的量级带**很宽**，是为抓"千倍量级 slip"设计，不是裁定异常材料；
- 两类错误**原理上检测不到**（载荷方向反向、单位量级写错）——数值完全自洽，只是答错问题；
- **截面面积的量级错误同样检测不到**（2026-10-10 审计实测，`tools/verify_audit_findings.py`）：
  面积放大 1000 倍时位移小 1000 倍，而 `check_model` 报 `ok`、四道闸门报 `verified`。
  `material_plausibility` 检查 E / ρ / f_y，**不检查 A**。原因是面积属于**尺度参数**——
  不存在"物理上不可能的截面面积"，只存在"与设计意图不符的面积"，这与载荷大小、载荷方向同类，
  要么靠人对照原始设计意图，要么需要额外的意图核对机制，不是量级带能解决的。

> **注意一个容易混淆的地方**：模型检查器回答的是"模型是否良定、量级是否可信"，
> 它**不检查设计约束**。设计约束（应力上限、挠度上限、屈曲安全系数）由优化器的
> `evaluate()` 检查，**`verify()` 从未接收 `Constraints` 参数**（见第九节）。

## 四、修复链（`repair.py`，会升级策略）

诊断器把失败分类为 6 类：`limit_point / branch_jump / divergence / singular_tangent / increment_exhausted / rigid_body_mechanism`。修复策略升级链：
`displacement_control → refined_increments → line_search → robust_combo`。

关键点（如实）：
- **切换控制变量是唯一能过极限点的修复**：载荷控制无法越过平衡路径的极大值（切线奇异），步长细化救不了（案例 A03 证明：40 步细步仍 `limit_point`）。
- **机构（mechanism）不是策略能修的**：故障在模型里，修复链**正确地不升级**（案例 A07、B04、盲测 F4 的 `attempts=[]` 都是这一行为）。
- 自动选择控制自由度：做一次线性分析取响应最大的自由度。

## 五、案例库 20 例的结果（`verisolv_cases`，2026-10-09 实测）

```
20 labelled cases run  [failure 9, normal 7, boundary 4]
detectable errors caught : 9/9
undetectable by design   : 2  B01_load_direction_reversed, B02_unit_slip_load_x1000
  of those, caught anyway: B02_unit_slip_load_x1000 -- caught by scale_consistency once the load magnitude exceeds the small-strain regime; the category (unit slip) remains undetectable in principle: a x10 slip of the same kind is measured silent
positive controls clean  : 9/9
repair acted correctly   : 20/20
missed                   : none
```

- 可检测错误 9/9 抓中；阳性对照 9/9 干净；修复行为 20/20 正确；漏抓 0。
  （`repair acted correctly : 20/20` 的语义是"20 条里没有一条的修复行为与预期不符"。
  **逐条计数（2026-10-11 第五轮复核，`python -m verisolv cases` 重跑逐行核对）**：
  首解即收敛 **14 条**（A02, A04, A05, N01, N02, E02, E00, E03, R01, R02, R03, B01, B02, B03，
  其中 A02/E03 虽收敛但落在非预期分支——修复链无需介入）；
  首解未收敛 **6 条**（A01, A03, A06, A07, E01, B04），其中**真正调用了修复链**的就是这 6 条；
  修复链救回 **4 条**（A01, A03, A06, E01）；A07（机构）与 B04（缺约束）按设计**不救**，
  修复链正确地不升级。它**不是**"20 条全部经过修复验证"。
- 两条"原理上检测不到"（B01 载荷反向、B02 单位 slip）被点名；B02 的实例（×1000 量级）被 `scale_consistency` 在位移超出小应变适用域时系统性抓到，但"单位写错"这一类别本身仍不可检测——实测 ×10 量级同类滑移完全静默（`tools/acceptance_scale_fix.py`：`-500,000 N → PASSED`，`-5,000,000 N → FAILED`）。

## 六、外部对照的关键数字（逐字取自已产出的证据文件）

| 项 | 值 | 说明 |
|---|---|---|
| 解析解对照（R01/R02/R03 相对误差） | 6.11e-16 / 4.58e-16 / 2.34e-16 | 位移控制到指定顶点挠度，比对**顶点力** |
| 跨库交叉验证（PyNiteFEA，顶点挠度相对差） | 5 N → 6.794e-8；设计载荷 50 kN → **7.139e-4** | 完整梯梯：5 N 6.794e-8 / 50 N 6.813e-8 / 500 N 6.989e-8 / 5000 N 8.814e-8 / 50000 N 7.139e-4。头条 6.8e-8 是**最小载荷**处值，引用时必须带载荷水平 |
| 步长细化一致性（位移相对差） | 1e-10 | 同一求解器加密复算 |
| 全局平衡（力/力矩不平衡） | 5.8e-10 | 变形后坐标 |
| 分支跳变 | 0.178 m = 中位增量的 1058.6 倍 | `path_continuity` 检测到的跳分支签名 |

**极限载荷的取样分辨率**（`docs/reproduce.md` 可复现）：极限载荷是位移控制路径上离散采样点的最大值，
步长越细越接近真值——40 步 7957.60 N、120 步 7962.69 N、400 步 7963.01 N、闭式解 7963.2 N。
**提交材料统一用 ≈ 7963 N**，不引用 40 步的 7957.7 N。

## 七、已知的验证层自身缺陷（如实记录）

- `verify.py` 的 `check_global_equilibrium` 早期版本用**参考坐标**算力矩，在几何非线性下误差随位移增长（`runs/` 记录：修正前力矩不平衡 3.665e-04，修正后 5.829e-10，降六个数量级）。
- `checkmodel.py` 的 `check_scale_consistency` 早期版本用 `Σ(E·A/L)`（**所有杆件轴向刚度之和**，不是结构刚度）估计位移，对参考悬臂偏小约 **890 倍**，导致该检查**对载荷型过载从未生效**——×1000 载荷下 1.41 m 跨度的结构位移 4.17 m，检查仍报 `PASSED`。
  该缺陷由盲测诊断（`docs/blind-diagnosis.md` 的 F6）发现，2026-10-09 修复为一次线性解估计，修复验证见 `docs/fixes.md`。
- 这两条是"验证不是橡皮图章"的直接证据：**验证层自己也被反复抓出 bug 并修正**。

## 八、验证层的能力边界（2026-10-10 对抗性审计的结论）

审计（`docs/audit-report.md`）尝试证伪本项目的每一条结论，以下**未能证伪**：
闭式解一致性（含两份实现逐行核对、换面积参数、超出小变形域复算）、跨库交叉验证的独立性
（`TINY_I=1e-14` 有量化敏感性依据，非拟合）、"两项闸门不独立"的结论本身、案例库数字的可复现性。

以下**被确认为盲点**并已如实披露：
1. **意图类错误**：载荷大小、载荷方向、单位量级、**截面面积量级**——数值全自洽，模型也良定，
   只有对照原始设计意图才能发现。
2. **设计约束不在 `verify()` 覆盖范围内**（见第九节）。
3. **模量在量级带内的错值**（2026-10-11 外部评审独立发现，本輪构造验证）：E = 21 GPa
   （默认 210 GPa 的 1/10，**仍在 `material_plausibility` 带宽 1e6–1e12 Pa 之内**），
   四道数值闸门全过 + `verified`，位移错 ~9–10 倍。与"面积量级盲点"同类：**在合理带内、
   数值自洽、但答错问题**。
4. **载荷全加在全约束支座节点**（2026-10-11 外部评审独立发现，本輪构造验证）：
   载荷分量加在双 DOF 均被约束的节点上时，结构零响应，四道数值闸门全过 + `verified`，
   与"面积量级盲点"同类。
5. **位移控制下 `step_refinement` 闸门近乎空转**：位移控制的终点是**强加**的（同一目标值），
   2N 步与 N 步在终点必然相同；真正变化的量（路径峰值载荷）不被该闸门比较。因此该闸门
   在位移控制下只验证"收敛复现性"，不验证"路径载荷精度"。

## 九、`verify()` 与设计约束的分工（必须分清）

优化器报告 `verdict=verified` 时，**这个 verdict 覆盖的是数值自洽性，不是设计约束**。

| 问题 | 谁回答 | 检查什么 |
|---|---|---|
| 这个解是不是方程组的真解？ | `verify()`（四道闸门） | 残差、全局平衡、路径连续性、步长加密 |
| 这个解满足应力/挠度/屈曲要求吗？ | `optimize.evaluate()` | `Constraints`：`max_stress` / `max_deflection` / `buckling_factor` |

代码事实：`optimize.py` 里 `verify()` 的调用是 `verify(model, result, **(verify_kwargs or {}))`，
**从未接收 `Constraints`**。因此"`verdict=verified`"与"满足设计约束"是**两件事**，
把它们读成一件事会高估优化结果的保证强度。

另外：`pattern_search` 是**坐标模式搜索**，不是全局优化算法。**"128.72 kg"是当前搜索找到的最轻可行设计，
不是数学意义上的全局最优解。** 图表与文字中不应使用"最优"这一措辞。
