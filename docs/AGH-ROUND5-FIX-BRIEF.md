## 1. 缺陷一：GCI 观测阶公式符号倒置（**最严重**）

### 1.1 事实（队长已独立复现）

`verisolv/gci.py` 的观测阶公式，相对它**自己声明的**"f1 = coarsest, f3 = finest"约定，
**比值方向反了**。

**决定性测试**（不看它自己的自测，用**构造上已知阶**的序列）：

```
f = f_exact + C·h^p,  h = 1, 1/2, 1/4   （按文档约定：粗 → 细）

p_true = 2.0  →  实报 p = -2.0000   status = reject
p_true = 1.0  →  实报 p = -1.0000   status = reject
p_true = 3.0  →  实报 p = -3.0000   status = reject
   同一个序列倒过来喂（细 → 粗）:
p_true = 2.0  →  实报 p = +2.0000
```

**一个教科书级收敛序列，按文档约定喂进去，被判为"阶为负 → 拒绝"。**

### 1.2 为什么自测没发现——**循环自证**

`tools/check_gci.py` 的合成样本**恰好按与 docstring 相反的次序**喂入，
**两个错误互相抵消**，所以"5 个已知收敛阶全部精确恢复"是**假的自证**。

**这是本轮最该记住的教训：一个自测如果和被测代码共享同一个错误假设，它证明不了任何事。**

### 1.3 真实序列的后果

```
n = 40/80/160  峰值载荷:  7959.445105 → 7960.520968 → 7963.136754
增量（粗→细）:            +1.075863      +2.615786
                          ← 增量在**递增**，这是发散特征，不是收敛

正确观测阶:  -1.2818      →  Richardson/GCI **不适用**，正确判定是 **reject**
闸门实报:    +1.2818  conditional  GCI(fine) = 0.00485 %
```

**所以那个 `0.00485%` 是无效数字。** 我们把它当作证据写进了 `README.md`、
`EVIDENCE.md`、`docs/upgrade-report.md`、`COMPLETION-SUMMARY.md`。

### 1.4 要做的

**第一步：先写一个独立的、不依赖被测代码的判据。**

新建 `tools/verify_gci_formula.py`（**队长已经写好了一个版本，在仓库里，你可以直接用或重写**），
要求：用 `f = f_exact + C·h^p` 构造**构造上已知阶**的序列，按**文档声明的次序**喂进去，
检查返回的 p 是否等于 p_true。**这个测试必须在修复前失败、修复后通过。**

**第二步：修 `gci.py` 的观测阶公式。**

让它满足：按"粗→细"喂入一个单调收敛（增量递减）的序列，返回**正的** p。
必须同时满足：**增量递增的序列返回负阶 → reject。**

**第三步：修 `tools/check_gci.py`。**

它的合成样本次序必须与 `gci.py` 的 docstring 约定**一致**，不能靠两个错误抵消。
**修完后必须能通过第一步那个独立判据。**

**第四步：检查渐近比是不是一个独立判据。**

评审指出：`asymptotic_ratio` **代数上恒等于 `r^(2p)`**——如果是这样，它**不携带任何 p 之外的信息**，
不是独立检查。而且接受带 `[0.7, 3.0]` 是按 `r=1.3` 标定的，我们实际用 `r=2`。

**你要做的**：
- 验证这个代数恒等式是否成立（自己推一遍）
- 对照文献核对渐近比的**标准定义**（Roache / Celik et al. 2008 的 "Procedure for Estimating and
  Reporting of Uncertainty Due to Discretization"）
- 如果我们的定义确实错了，**改对**；如果恒等式成立，**改文档说明它不是一个独立判据**

**第五步：修正所有对外声称。**

修完后 GCI 在这个问题上的**正确结论是 `reject`**（序列不在渐近区）。
因此必须把 `0.00485%` 从**所有**地方撤回或改写为：

> 我们实现了 GCI（Roache / ASME V&V 20）。在真实问题上，我们**没能**得到可用的误差带——
> 载荷步细化序列的增量是递增的，不在渐近区，闸门正确判定为 `reject`。
> **我们没有量化的离散误差带。这是一个未解决的问题，不是已完成的成果。**

**并如实说明**：GCI 公式原先实现错误（比值方向反），由外部评审发现，现已修复；
修复后的自测由**独立的、不共享代码的判据**验证。

### 1.5 验收

| # | 判据 | 通过标准 |
|---|---|---|
| 1 | 独立判据（不 import 被测代码的公式） | 构造上已知阶的序列，按文档约定喂入，p 必须等于 p_true（1e-6 精度），且判定为 pass/conditional |
| 2 | 反向序列 | 增量递增的序列必须返回负阶并 `reject` |
| 3 | 真实序列 | `n=40/80/160` 必须 `reject`（增量递增） |
| 4 | 旧的循环自证 | `check_gci.py` 必须**不再**依赖次序抵消 |
| 5 | 对外声称 | 全项目搜 `0.00485` / `SOURCE-BACKED.*GCI`，不得再有"我们得到了误差带"的表述 |

**队长会亲自动手跑第 1、2、3 条，不看你的报告。**

## 2. 缺陷二：MMS 名不副实（**建议撤回，不建议修**）

### 2.1 评审的指控

- **制造源项从未注入求解器**（位移是强加的，不是解出来的）
- **SymPy 源项两处推导错误**：应变应为 `a + a²/2` 而不是 `a`；节点力应为 `±N` 而不是 `±N/2`
- **"theory_p = 1" 与饱和的实测自相矛盾**

### 2.2 队长判断：**撤回，不修**

理由：**MMS 测量的是"空间离散的观测收敛阶"，而我们的模型没有空间网格**——
节点是给定的，唯一的离散化参数是载荷步。**没有网格可细化，就测不了空间收敛阶。**

这和我们自己对 GCI 的说法是同一个问题：**我们没有网格。**

**所以正确做法是撤回 MMS 的有效性声称，而不是硬修。** 修它需要改单元定义或引入网格，
那超出半天预算，而且会触及冻结的求解器内核。

### 2.3 要做的

1. 把 `docs/mms.md` 改写为 **"MMS 尝试记录（未成功）"**：
   - 说明我们尝试了什么
   - **逐条列出评审指出的三处错误**
   - **明确声明：这不是一个有效的 MMS，我们不声称任何收敛阶**
   - 说明**根本原因**：我们的模型没有空间网格，MMS 的核心（空间细化测阶）在本框架内不适用
2. `tools/mms_verification.py` 保留但**改名或加显著头部警告**，说明它测的不是 MMS
3. 从 `EVIDENCE.md`、`README.md`、`docs/upgrade-report.md` 撤回所有 MMS"通过/已验证"的表述

**验收**：全项目搜 `MMS`，每一处都必须要么是"尝试/失败/撤回"，要么是"我们无法做 MMS 因为无网格"。
**不允许任何地方出现"MMS 验证通过"这类陈述。**

## 5. 缺陷五：跨库验证的表述问题（三处）

### 5.1 头条数字的位置

`6.794e-8` 是**最小载荷 5 N（线性极限）**处的顶点挠度相对差。
完整梯子（评审实测）：

```
载荷            5 N        50 N       500 N      5000 N     50000 N（设计载荷）
顶点挠度相对差  6.794e-8   6.813e-8   6.989e-8   8.814e-8   7.139e-4
```

**设计载荷处的差是 7.14e-4，比头条数字大 1 万倍。**

**要做的**：`README.md` / `EVIDENCE.md` / `docs/verification.md` 引用 `6.8e-8` 时，
**必须同时给出载荷水平**，并补上完整梯子表。

### 5.2 "每降一个数量级，差距同降一个数量级"是错的

`docs/verification.md:23` 这样写。实测 5 N→5000 N 是**平坦地板（~7e-8，TINY_I 截断）**，
到 50 kN 反而**跳升 80 倍**。

**要做的**：改为如实描述——"小载荷段是平台（受 PyNite 侧框架单元模拟的截断限制），
设计载荷处升至 7.1e-4"。

### 5.3 `cross_validate.py` 说误差"按 I² 下降"是错的

评审独立扫描 `TINY_I` 从 1e-8 到 1e-16：**误差线性随 I 下降**，不是二次。

**要做的**：改注释。

**验收**：队长会自己跑一遍 `TINY_I` 扫描核对。
